# Quality Platform frontend

The React interface uses TanStack Router, Rsbuild, Tailwind CSS and [Arc UI](https://uiarc.dev/) components. FastAPI serves the **built** app and its JSON API from one origin. End users install a wheel that already contains this build; Bun is needed only when developing or building a release from source.

## Develop from source

From the repository root:

```sh
uv sync --locked --dev
cd web
bun install --frozen-lockfile
bun run build
bunx tsc --noEmit
bun run lint
cd ..
uv run quality-platform setup
uv run quality-platform dashboard
```

These launcher commands use the developer's persistent `~/.quality-platform` data, just like an installed release. Do not use an existing personal workspace for destructive test scenarios. The Python tests initialize disposable state with temporary paths and fake models.

Open the FastAPI origin printed by the launcher, normally `http://127.0.0.1:8000`, not the standalone Rsbuild dev server. `bun run dev` and `bun run preview` do not start FastAPI or a worker and have no API proxy configured; they are not the authenticated application workflow. See [local Web operations](../docs/web.md) for low-level worker/server commands.

In a source checkout, the server reads Git-ignored `web/dist/`. Build after pulling frontend changes, then refresh the browser. If the server started without the static directory, restart it after building so `/static/` is mounted. Missing `index.html` returns HTTP 503 with build instructions. Installed wheels instead read the bundled build through `quality_platform.resources.runtime_root()`; users do not build or edit that resource directory.

## Structure

- `src/routes/_app/route.tsx` composes the protected sidebar/main-content shell. Page routes cover projects, workflows, source evidence, artifact versions, activity, benchmark reports, evaluation review, and settings.
- `src/routes/_auth/` contains the unbranded, password-only owner sign-in screen. `GET /api/session` returns the session-bound CSRF token; successful login rotates both HttpOnly cookies. API keys never reach the browser.
- `src/routes/_app/settings.tsx` groups account/workspace, model defaults, and provider connection status into Arc tabs. Account and workspace forms use dedicated endpoints; model configuration uses versioned settings.
- `src/features/workspace/ui.tsx` and `ui.module.css` own shared headings, panels, summaries, form fields, statuses, and action forms.
- `src/lib/api.ts` owns same-origin requests, session state, resource loading, and action submission. `useAction` supplies CSRF and idempotency headers and retains a key across retries of the same payload. Account updates use the API helper directly.
- `src/components/arc/foundation.css` owns the palette, typography and component tokens. `src/assets/css/globals.css` only loads Tailwind and maps utility colors and fonts to Arc tokens; it does not redeclare the foundation.
- `src/routeTree.gen.ts` is generated by the TanStack Router build plugin; edit route source files instead.

Keep the sidebar/main-content structure, Instrument Sans and Spline Sans Mono, zero-radius components, and login without branding. Follow the repository [Development Guidelines](../AGENTS.md) when changing UI or API behavior. Keep browser and API on the same origin; do not add CORS or expose session cookies to JavaScript to bypass authentication failures.

## Checks

Run from `web/`:

```sh
bunx tsc --noEmit
bun run lint
bun run build
```

Check formatting on edited files with `bunx oxfmt --check <paths>`; use `--write` for those files when needed. `bun run format` rewrites the entire frontend and also applies lint fixes, so it is not a scoped formatting command. Inspect rendered desktop/mobile states against the real backend for appearance changes; DOM or type checks alone do not verify the layout.

The frontend does not run the worker or paid model calls automatically. Queuing a provider run, retry, or resume requires explicit authorization; reading pages and reports does not enqueue work. Release wheel commands and the isolated installation smoke test are in the [root README](../README.md#build-a-release-from-source).
